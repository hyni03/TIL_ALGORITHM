## 문제 설명

괄호가 바르게 짝지어졌다는 것은 `(` 문자로 열렸으면 반드시 짝지어서 `)` 문자로 닫혀야 한다는 뜻입니다.

문자열 `s`가 주어졌을 때 올바른 괄호 문자열이면 `true`, 그렇지 않으면 `false`를 반환합니다.

### 제한사항
- 문자열 `s`의 길이는 100,000 이하입니다.
- 문자열은 `(` 또는 `)`로만 이루어져 있습니다.

<br>

## 접근법

**스택(Stack)** 을 사용해서 풀었습니다. 정석이죵 ㅎㅎ

`(`가 나오면 스택에 넣고, `)`가 나오면 이전에 열린 괄호를 하나 꺼내도록 하는데 <br>
단순히 여는 괄호와 닫는 괄호의 **개수가 같다고** 올바른 괄호는 아니기 때문에 검증을 거쳐야 합니당

```text
")(" → 괄호 개수는 같지만 올바르지 않음!
```

닫는 괄호가 나왔을 때 짝지을 여는 괄호가 없는 경우를 바로 걸러야 합니다.

<br>

## 해결법

### 1. 여는 괄호가 나오면 push

```cpp
if (a[i] == '(')
    s1.push(a[i]);
```

나중에 나올 닫는 괄호와 짝을 맞추기 위해 스택에 저장합니다.

### 2. 닫는 괄호가 나오면 pop

```cpp
else if (a[i] == ')' && s1.empty() == 0)
    s1.pop();
```

스택이 비어 있지 않다면 이전에 열린 괄호가 있다는 뜻이므로 하나 제거합니다.

반대로 `)`가 나왔는데 스택이 비어 있다면 짝이 맞지 않으므로 바로 `false`입니다.

### 3. 마지막에 스택이 비어 있는지 확인

```cpp
if (s1.empty() == 0)
    answer = false;
```

문자열을 끝까지 검사해도 `(`가 남아 있다면 닫히지 않은 괄호가 있다는 뜻입니다.

<br>

## 최종 결과

### 최종 코드

```cpp
#include <string>
#include <stack>
using namespace std;

bool solution(string s) {
    stack<char> st;

    for (char c : s) {
        if (c == '(') {
            st.push(c);
        } else {
            if (st.empty()) return false;
            st.pop();
        }
    }

    return st.empty();
}
```

### 추가 개선: 스택 대신 카운터 사용하기

생각해 보니 이 문제는 괄호 종류가 `()` 하나뿐이라서 **스택에 문자 자체를 저장할 필요도 없었습니다.**

아직 짝을 찾지 못한 `(`의 개수만 기억하면 됩니다.

```cpp
#include <string>
using namespace std;

bool solution(string s) {
    int cnt = 0;

    for (char c : s) {
        if (c == '(') cnt++;
        else cnt--;

        if (cnt < 0) return false;
    }

    return cnt == 0;
}
```

```text
"(())" → 1 → 2 → 1 → 0 → true
")("   → -1 → 바로 false
"(()"  → 1 → 2 → 1 → false
```

- **시간복잡도: O(N)**
- **추가 공간복잡도: O(1)** — 정수 변수 하나만 사용합니다.

단, 괄호 종류가 `()`, `{}`, `[]`처럼 여러 개라면 종류와 순서까지 확인해야 하므로 스택이 필요합니다.

## 후기

처음에는 여는 괄호를 스택에 넣고 닫는 괄호가 나오면 제거하는 방식으로 풀었습니다.

이때 중요한 건 **스택이 비어 있는데 닫는 괄호가 나오면 바로 실패**하고, **모든 문자를 확인한 뒤에도 스택이 비어 있어야 한다**는 점이었습니다.

그리고 이 문제처럼 괄호가 한 종류일 때는 스택을 직접 사용하지 않고 카운터 하나로도 풀 수 있다는 것!!

```text
짝을 맞추면서 이전 상태를 기억해야 한다 → 스택 생각하기!
괄호 종류가 하나이고 개수만 관리하면 된다 → 카운터로 최적화 가능!
```

앞으로 괄호 문제를 보면 단순히 개수만 맞는지 확인하는 게 아니라 **중간에 닫는 괄호가 더 많아지는 순간이 있는지**부터 체크해야겠습니다.
